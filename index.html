01先搞清楚三件事

Hugging Face 常被误以为是「一个下模型的地方」，其实它是三层结构：本地工具负责搬运，云端 Hub 负责托管，上层生态负责把模型真正跑起来。

图 1　Hugging Face 生态的三层结构

Hub 上的四类东西

类型是什么典型路径
model模型权重 + 配置 + 分词器，下模型主要就是下这个Qwen/Qwen3-0.6B
dataset数据集，可含 parquet / arrow 等多种格式wikitext
space跑在 Hub 上的小应用（Gradio / Docker / 静态页）username/my-space
bucket纯对象存储，适合放 checkpoint、日志，不要求是标准仓库结构hf://buckets/user/bucket
最重要的版本变更：huggingface-cli 已经不存在了。它在 huggingface_hub 0.34（2025-07）被改名为 hf，并在 1.0（2025-10）中彻底移除。网上 2025 年年中之前的教程里那些 huggingface-cli download ... 命令现在跑不通，全部换成 hf，登录相关命令收到 hf auth 子命令下。

一次典型工作流

1登录hf auth login
2找模型hf models ls
3下载hf download
4本地跑transformers
5传回去hf upload

02安装与登录

安装

两种装法，二选一即可：

# 方式 A：pip 安装（通常你已经有 Python 环境，用它最省事）
pip install -U "huggingface_hub[cli]"

# 方式 B：官方独立安装脚本（不依赖 Python，装在 ~/.local/bin/hf）
curl -LsSf https://hf.co/cli/install.sh | bash -s

# Windows PowerShell
powershell -ExecutionPolicy ByPass -c "irm https://hf.co/cli/install.ps1 | iex"

装完先自检：

hf version     # 版本号，1.x 才算新 CLI
hf env         # 打印完整环境信息：Python 版本、缓存目录、当前 endpoint、token 来源
排查网络问题请第一眼看 hf env。它会明确告诉你 HF_ENDPOINT 当前是什么值、缓存目录在哪 —— 九成的「为什么还是走官方站」都是环境变量没生效。

登录

先生成 Token：打开 huggingface.co/settings/tokens，新建一个 Read 权限即可（要上传则选 Write）。

命令作用
hf auth login交互式登录，可走浏览器授权或粘贴 Token
hf auth login --token $HF_TOKEN非交互登录，适合 CI / 脚本
hf auth whoami确认当前登录的是哪个账号
hf auth list列出本机保存的所有 Token
hf auth switch多账号之间切换
hf auth token把当前 Token 打到 stdout（不要提交进 Git）
hf auth logout登出指定 Token

CI 或容器环境里，直接给环境变量更干净，不需要写文件：

export HF_TOKEN=hf_xxxxxxxxxxxxxxxxxxxxx
hf download Qwen/Qwen3-0.6B      # 自动读取 HF_TOKEN

03下载模型与数据集

下载只用一条命令：hf download <REPO_ID>。模型是默认类型，所以下模型不用加任何类型参数。

命令结构

hf download REPO_ID [--type model|dataset|space] [选项...]
#  ↓            要下的仓库   不写默认 model
#  例：hf download Qwen/Qwen3-0.6B --local-dir ./qwen3

常用参数

参数作用
--local-dir ./qwen3落到你指定的目录，里面是真实文件而不是软链接，所见即所得
--include "*.safetensors"只下匹配的文件，可写多个模式
--exclude "*.bin" "*.h5"排除匹配的文件，常用于跳过用不上的重复权重
--revision <分支/标签/commit>锁定版本，例如 main、v1.0、refs/pr/1
--type dataset|space指定仓库类型（旧版本写作 --repo-type，两者择一，报错就换另一个）
--cache-dir <路径>临时指定缓存目录
--max-workers 8并发下载线程数，网络好时可以调大
--dry-run只列出会下载哪些文件，不真下 —— 摸体积时很有用
--force-download强制重新下载，忽略已有缓存

常见场景示例

# 1. 整仓下载到普通目录
hf download Qwen/Qwen3-0.6B --local-dir ./qwen3

# 2. 只要 safetensors 权重和 json 配置，跳过 .bin
hf download Qwen/Qwen3-0.6B --include "*.safetensors" "*.json"

# 3. 只下某一个文件（体积大时先看看大小）
hf download Qwen/Qwen3-0.6B --include "config.json"

# 4. 先空跑看清单，再决定下不下
hf download meta-llama/Llama-3.1-8B --dry-run

# 5. 下数据集
hf download --type dataset wikitext --local-dir ./wikitext
#   旧版 CLI 请写成 --repo-type dataset

# 6. 锁定某个版本（可复现）
hf download Qwen/Qwen3-0.6B --revision v0.1.0

# 7. 下别人的 Space 源码来改
hf download --type space username/my-space --local-dir ./my-space
不确定模型叫什么名字？在网页搜索框直接搜，URL 里 huggingface.co/<用户名>/<仓库名> 的斜杠后那段就是 REPO_ID。也可以用 hf models ls 在终端里浏览。

04搞懂本地缓存

不加 --local-dir 时，文件会进入缓存目录。这个目录的结构第一次看会有点懵，因为它用了「真实文件 + 软链接视图」两级设计：

图 2　缓存目录：blobs 存真实文件，snapshots 只是指向它们的软链接

为什么要这么设计？因为同一个文件可能被多个 commit 引用。真实数据只存一份放在 blobs/ 里（用内容哈希命名，天然去重），snapshots/<commit>/ 下按「文件名 → blob」组织成软链接，于是切版本、回滚只是换一批链接，不需要重新下载 GB 级文件。

缓存管理命令

命令作用
hf cache list列出已缓存的仓库及占用空间
hf cache list --revisions连各个 revision 一起列，找出旧 commit 占了多少
hf cache prune清掉不再被任何 ref 引用的游离 revision
hf cache rm <repo_id>删除某个仓库的全部缓存，腾空间主用这条
hf cache verify <repo_id>校验下载完整性，怀疑文件损坏时用
# 看看谁最占地方
hf cache list

# 删掉一个大模型的缓存
hf cache rm Qwen/Qwen3-0.6B

# 清理历史版本留下的孤儿文件
hf cache prune
两个实用技巧。① 缓存路径可用环境变量整体搬走，模型多了建议放到大容量盘：export HF_HOME=/Volumes/data/hf。② 完全离线跑时设 export HF_HUB_OFFLINE=1，程序只用本地缓存，不会因为探测网络而卡启动。

05国内网络加速

默认访问的是境外的 huggingface.co，小文件还能忍，几 GB 的权重基本会卡在 0% 或者中途断掉。解法是换一个端点：

图 3　换一个 endpoint，链路就留在国内

设置方法

镜像只认一个环境变量 HF_ENDPOINT，设完之后 hf 命令行、transformers、datasets 全都会自动跟着走。

# macOS / Linux —— 临时生效（当前这个终端窗口）
export HF_ENDPOINT=https://hf-mirror.com

# macOS / Linux —— 永久生效，写进 shell 配置
echo 'export HF_ENDPOINT=https://hf-mirror.com' >> ~/.zshrc
source ~/.zshrc

# Windows PowerShell —— 临时
$env:HF_ENDPOINT = "https://hf-mirror.com"

# Windows —— 永久（写进用户环境变量，重开终端生效）
setx HF_ENDPOINT "https://hf-mirror.com"

验证是否真的生效：

hf env | grep -i endpoint
# 应输出 HF_ENDPOINT=https://hf-mirror.com

# 或者直接下个小模型试试速度
hf download Qwen/Qwen3-0.6B --local-dir /tmp/qwen3-test
只设环境变量，不要动 git 的 remote。镜像只是把 HTTPS 请求改到国内，仓库地址仍然用官方的那套路径；手动改 git remote 反而会导致 hf upload 走错地方。

再快一点

手段说明
HF_XET_HIGH_PERFORMANCE=1启用 Xet 分块传输的高性能模式，huggingface_hub 1.x 默认已装好 hf_xet
--max-workers 8提高并发数，网络稳定时有效
先 --dry-run看清总共要下多少、有哪些用不上的格式（.bin / .msgpack），再用 --include 精准下载
大容量缓存盘export HF_HOME=/大容量盘/hf，避免反复删了又下

注：老教程里的 hf_transfer（pip install hf_transfer + HF_HUB_ENABLE_HF_TRANSFER=1）在 huggingface_hub 1.0 中已被 hf_xet 取代，新环境不必再装。

06上传与仓库管理

建仓库

最直观的方式是网页右上角 New → Model / Dataset / Space。也可以跳过这步：hf upload 在目标仓库不存在时会自动创建。

上传

hf upload REPO_ID LOCAL_PATH [选项...]

# 传单个文件
hf upload username/my-cool-model ./model.safetensors

# 传整个目录（本地目录内容会成为仓库根目录）
hf upload username/my-cool-model ./my-model-folder

# 传一份数据集
hf upload username/my-dataset ./data --type dataset

# 建私有仓库 + 自定义 commit 信息
hf upload username/my-model ./my-model-folder --private --commit-message "add v2 weights"

# 顺手删掉仓库里已经没用的旧文件
hf upload username/my-model ./my-model-folder --delete "old/*"

# 先提 PR 而不直接改主干
hf upload username/my-model ./my-model-folder --create-pr

上传参数

参数作用
--private创建时设为私有仓库
--type model|dataset|space指定仓库类型
--include / --exclude按模式挑选要传的文件
--delete "old/*"上传同时删除远端匹配路径
--commit-message / --commit-description自定义提交信息
--create-pr走 Pull Request 流程，便于多人协作审核
--every 10每 10 分钟自动提交一次，适合边训练边传 checkpoint
超过几 GB 的目录用 hf upload-large-folder。它带断点续传，网络中断后重跑不会从头开始，最后还能用 hf cache verify 校验完整性。注意在最新版本里该命令已标记为 deprecated（官方建议直接用 hf upload），但大目录场景下它的续传体验仍然更好，看你装的版本支持哪个。

另一种路线：git

需要精细控制分支、历史或者接进现有 Git 流程时，可以直接当普通 git 仓库操作。大文件由 git-lfs 托管：

pip install -U "huggingface_hub[cli]"   # 同时提供 hf 命令用于配好认证
git lfs install
hf auth login --add-to-git-credential

git clone https://huggingface.co/username/my-model
cd my-model
git lfs track "*.safetensors"          # 让大文件走 LFS
git add .
git commit -m "add weights"
git push

顺带一提：buckets

如果你只是想要一块云端存储放 checkpoint、日志或中间产物，不需要「仓库 + 版本 + README」这套结构，用 bucket 更合适：

hf buckets create my-bucket --private
hf buckets sync ./checkpoints hf://buckets/username/my-bucket   # 双向同步目录
hf buckets cp ./run.log hf://buckets/username/my-bucket/run.log
hf buckets list

07在 Python 里调用

装依赖

pip install -U transformers torch

最简用法：三行跑起来

from transformers import pipeline

pipe = pipeline("text-generation", model="Qwen/Qwen3-0.6B")
print(pipe("你好，请用一句话介绍杭州：", max_new_tokens=64))

第一次运行会自动下载权重到缓存目录。想改成从别处加载或避免重复检查，可以直接指定本地目录：model="./qwen3"。

用 huggingface_hub 只管搬运

只想下载、不想拉整个 transformers 时，huggingface_hub 就够了：

from huggingface_hub import snapshot_download, hf_hub_download, HfApi, login

login()  # 交互式登录，等价于 hf auth login

# 整仓下载到指定目录
snapshot_download(repo_id="Qwen/Qwen3-0.6B", local_dir="./qwen3")

# 只要其中一个文件，返回值是文件的本地路径
p = hf_hub_download(repo_id="Qwen/Qwen3-0.6B", filename="config.json")
print(p)

# 排除体积大的格式
snapshot_download(
    repo_id="Qwen/Qwen3-0.6B",
    local_dir="./qwen3-lite",
    ignore_patterns=["*.bin", "*.h5"],
)

# 上传目录
api = HfApi()
api.upload_folder(
    folder_path="./my-model",
    repo_id="username/my-model",
    repo_type="model",
)

代码里也可以不登录，靠环境变量：export HF_TOKEN=hf_xxx 后所有 SDK 调用都会自动带上认证。

transformers v5 的几个变化（2026-01 发布）。这是一次动了地基的大版本：
① 只支持 PyTorch，TensorFlow 与 JAX/Flax 支持已整体移除，老的 TF 代码需要迁移；
② 分词器统一走 tokenizers 后端，不再区分 fast/slow，use_fast= 这类参数正在退场；
③ 图像处理器只保留 torchvision 支持的 fast 版本；
④ 量化从「一堆加载开关」变成一等配置对象；
⑤ 定位调整为模型定义层 —— 训练交给第三方 trainer，服务化交给 vLLM / SGLang，导出交给 llama.cpp / ExecuTorch / MLX。
连带的一条：TGI（Text Generation Inference）已归档，官方现在推荐用 vLLM 或 SGLang 做服务端推理，新项目别再从 TGI 起步。

08Spaces 部署一个应用

Spaces 是跑在 Hub 上的应用托管，免费档够做 demo。网页 New → Space，选 SDK（Gradio 最省事）和可见性即可。

仓库里必有的三个文件

my-space/
├── app.py              # 入口，Gradio 应用写这里
├── requirements.txt    # 依赖，Hub 会自动 pip install
└── README.md           # 顶部 front matter 决定标题、SDK、硬件

README.md 的 front matter 是关键配置，写错了应用起不来：

---
title: My First Space
colorFrom: blue
colorTo: green
sdk: gradio
sdk_version: 5.0.0
app_file: app.py
pinned: false
---

一个能跑的最小 app.py：

import gradio as gr

def greet(name):
    return f"你好，{name}！"

gr.Interface(fn=greet, inputs="text", outputs="text").launch()

部署与更新

# 把本地目录推上去（仓库不存在会自动建）
hf upload username/my-space ./my-space --type space

# 只改了一个文件
hf upload username/my-space ./my-space/app.py --type space

# 或者用 git 推送，改动会触发自动重新构建
git clone https://huggingface.co/spaces/username/my-space
cd my-space && git add . && git commit -m "update" && git push

推上去之后 Hub 会自动构建，日志在 Space 的 Logs 标签页里看。硬件默认 CPU basic（免费），需要 GPU 可在 Settings → Hardware 里换（按小时计费）。

除了 Spaces，还有一条托管路线是 Inference Endpoints，把模型部署成带自动扩缩容的 API：相关命令在 hf endpoints 下。

09排障速查表

现象原因处理
command not found: huggingface-cli该命令已在 huggingface_hub 1.0 中移除改用 hf，登录改用 hf auth login
hf: command not found装到了不在 PATH 的目录用 pip install -U "huggingface_hub[cli]" 重装，或把 ~/.local/bin 加进 PATH
下载长期停在 0%跨境链路export HF_ENDPOINT=https://hf-mirror.com 后用 hf env 确认已生效
跑得很慢但 hf env 显示 endpoint 正常环境变量只在当前终端生效，程序在别处启动写进 ~/.zshrc / ~/.bashrc，或改用 setx（Windows）
401 Unauthorized没登录或 Token 无效hf auth login，再用 hf auth whoami 确认账号
403 / You need to agree to share your contact informationgated 模型未接受许可打开模型页点 Agree；部分还需要等作者审批
error: unexpected argument '--type'CLI 版本偏旧换成 --repo-type，或 hf update 升级
缓存目录里全是看不懂的软链接和哈希名这是 snapshots + blobs 的正常结构想要普通文件就加 --local-dir
磁盘被吃满每个 commit 都留了一份视图hf cache list 找到大户 → hf cache rm <repo> → hf cache prune
上传中途断掉，重跑又从 0 开始单次 commit 太大换 hf upload-large-folder（支持续传），并按目录拆分
文件下载完但加载报损坏传输不完整hf cache verify <repo_id> 校验，然后加 --force-download 重下
离线环境下启动特别慢程序在探测网络export HF_HUB_OFFLINE=1，只用本地缓存
不想上报使用统计——export HF_HUB_DISABLE_TELEMETRY=1

诊断顺序

1看环境hf env
2看账号hf auth whoami
3看缓存hf cache list
4加 -v 重跑hf download -v

10一页速查卡

# ---------- 环境 ----------
pip install -U "huggingface_hub[cli]"
hf version && hf env
export HF_ENDPOINT=https://hf-mirror.com      # 国内加速
export HF_TOKEN=hf_xxx                        # 非交互认证
export HF_HOME=/大容量盘/hf                    # 缓存搬家

# ---------- 认证 ----------
hf auth login            # 登录
hf auth whoami           # 当前账号
hf auth list             # 已有 token
hf auth switch           # 多账号切换

# ---------- 下载 ----------
hf download Qwen/Qwen3-0.6B --local-dir ./qwen3
hf download Qwen/Qwen3-0.6B --include "*.safetensors" "*.json"
hf download Qwen/Qwen3-0.6B --dry-run
hf download --type dataset wikitext --local-dir ./wikitext
hf download --type space user/space --local-dir ./space

# ---------- 缓存 ----------
hf cache list
hf cache list --revisions
hf cache rm Qwen/Qwen3-0.6B
hf cache prune
hf cache verify Qwen/Qwen3-0.6B

# ---------- 上传 ----------
hf upload username/my-model ./model.safetensors
hf upload username/my-model ./folder --private --commit-message "v2"
hf upload username/my-dataset ./data --type dataset
hf upload username/my-space ./my-space --type space
hf upload-large-folder username/my-model ./big-folder     # 大目录续传

# ---------- 存储桶 ----------
hf buckets create my-bucket --private
hf buckets sync ./checkpoints hf://buckets/username/my-bucket
hf buckets list

# ---------- 其他 ----------
hf models ls             # 浏览模型
hf datasets info wikitext
hf jobs run python:3.12 python -c "print('hi')"
hf endpoints             # 管理推理端点
hf discussions list username/my-model
hf update                # 升级 CLI 自身
hf --help                # 发现更多

本指南基于 huggingface_hub 1.x 与 transformers 5.x 整理，核对时间 2026-09。
CLI 迭代很快（现在已是每周发布节奏），遇到参数对不上时先跑 hf <命令> --help 以本地实际输出为准。
